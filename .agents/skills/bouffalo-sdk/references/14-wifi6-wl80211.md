# Wi-Fi 6：FHOST 与 wl80211

先确认工程使用的栈，再查对应头文件、实现和示例。两个栈有部分同名 `wifi_mgmr` 类型和函数，但字段、初始化及行为不同，不能混合头文件或复制配置结构。无线共存、射频、网络协议和低功耗还要分别结合相关模块核查。

## 选择和构建

`examples/wifi/defconfig` 对 BL602 选择 Wi-Fi 4，其他分支选择 `CONFIG_WIFI6` 和 MACSW profile；其中 `CONFIG_WL80211=y` 时启用独立 `CONFIG_BL_WPA_SUPPLICANT`，否则启用 `CONFIG_FHOST`。这是该公共示例配置的选择规则，不是全部芯片能力矩阵。`examples/wifi/macsw_bare/defconfig` 显式使用 wl80211。

`components/wireless/CMakeLists.txt` 根据预编译 MACSW/FHOST 库是否存在选择库路径；wl80211 的 CMake 在 `src/` 存在时选择构建目录中的源码产物，否则查找对应芯片的 `lib/libwl80211_<chip>.a`。`library.mk` 在 profile 非空时构建 MACSW 和 FHOST，并在 `CONFIG_WL80211` 的 Make 变量非空时配置构建 wl80211；最终仍应核对目标 build 下的配置、编译命令和链接命令。`wl80211/src` 可能是独立仓库，记录版本和工作区状态时应分别检查 public 与 private 仓库。预编译 PHY 等库内部不在源码审查范围。

FHOST 的应用管理接口在 `components/wireless/wifi6/fhost/include/wifi_mgmr_ext.h`，配合 `components/wireless/wifi6/wifi6_lwip_adapter/`、FHOST 自带 supplicant 及 MACSW；wl80211 接口在 `components/wireless/wl80211/include/wifi_mgmr.h`、`components/wireless/wl80211/include/wl80211.h`，配合独立 `bl_wpa_supplicant`。连接管理、认证和 IP 协议栈是协作关系，不应画成所有栈共用的一条串行协议层。

## FHOST：初始化和 STA

`examples/wifi/sta/wifi_tcp/` 的非 BL602 分支先执行板级和 RF 初始化、启动 lwIP，再在任务中注册 `EV_WIFI`、创建 Wi-Fi 任务并调用 `fhost_init()`；`CODE_WIFI_ON_INIT_DONE` 后启动 manager，等待 `CODE_WIFI_ON_MGMR_DONE`。实际工程还应处理初始化失败和任务资源。

具体连接参数和调用顺序见 `examples/wifi/sta/wifi_tcp/` 与选中栈的头文件。

调用返回 0 表示连接请求已提交到该路径，不代表已关联、认证或拿到 IP；分别关注 `CODE_WIFI_ON_CONNECTED`、`CODE_WIFI_ON_GOT_IP`、`CODE_WIFI_ON_DISCONNECT` 及超时事件。`dhcp_timeout_event_only` 控制 DHCP 超时仅发事件还是使用原有断连/重连行为；静态 IPv4 参数见对应 API 的网络字节序约定。`extra_ies` 是借用指针，需保持至连接完成，长度上限 64；AKM 字符串按头文件要求使用大写和 NUL 结尾。

## FHOST：AP

使用清零的 `wifi_mgmr_ap_params_t`，明确提供 `ssid`、`key`、`akm`、信道及 `use_ipcfg/use_dhcpd`；调用 `wifi_mgmr_ap_start` 后关注 AP 事件。头文件规定：`key == NULL && akm != NULL` 会使用默认密码，正式产品应显式提供安全配置；SAE-only 需要 PMF=2。AP 与 STA 同时使用时避免 IPv4 子网重叠；动态改 AP IP 前遵循 API 对 DHCP server 的要求。ACS 启动最长可阻塞 60 秒，不要从 WPA/control 任务调用；已连接 STA 的信道优先。具体支持与约束以当前头文件和目标芯片为准。

## wl80211：入口及状态

`examples/wifi/macsw_bare/` 展示 `wifi_task_create()`、`tcpip_init()`、`wl80211_init()`、`wifi_mgmr_init()` 等入口。其 `wifi_mgmr_sta_connect_params_t` 的 `ssid` 和 `key` 是 NUL 结尾数组，没有 FHOST 的 `ssid_len/key_len` 字段；将数据复制进正确结构后调用 `wifi_mgmr_sta_connect()`，同样要等待连接和 IP 事件。`wifi_mgmr_init` 在 wl80211 的返回类型为 `void`，与 FHOST 不同。

接口声明不等于功能已实现：当前 wl80211 `wifi_mgmr_sta_scanlist`、部分 AP 状态查询等源码返回 -1，静态 IP 的头文件注释称未实现，但 `COMPAT_WIFI_MGMR` 路径的 `wl80211/lwip.c` 实际提供 `wifi_mgmr_sta_ip_set`，设置 netif 地址，DNS 非零时更新 DNS 服务器；实际行为应结合目标配置核验。相反，autoconnect 的 public 头文件注释仍称 stub，但当前 `wifi_mgmr.c` 中 enable/disable 实际修改状态；涉及兼容性时以选中版本实现及验证结果为准。不同栈、不同版本的 CLI 及输出格式也需在当前固件确认。

## wl80211 排查路径

按阶段收集日志，而不是把所有失败归为密码问题：

1. 检查连接请求参数与 `wl80211_sta_connect` 返回值、扫描结果、关联确认中的 firmware status 和 IEEE reason。
2. 对加密连接，沿 `wl80211/src/macsw/connect.c`、`supplicant.c` 和 `bl_wpa_supplicant` 检查关联 IE、EAPOL、握手及 key 安装；认证成功、control-port 确认和连接事件是不同观察点。开放网络走不同分支。
3. 非 NuttX manager 在 `use_dhcp` 为真时于连接后启动 DHCP，当前实现 15 秒未获取地址会断连；P2P CLIENT 另有强制启用 DHCP 分支。`CODE_WIFI_ON_GOT_IP` 与关联事件是不同阶段。不要把某个认证失败状态直接解释为密码一定错误。
4. IP 已取得但业务不通时，检查 `wl80211/lwip.c` 的 netif、link、RX 交付、TX 的 pbuf 和返回值，再结合 `src/macsw/rx.c`、`tx.c` 的 VIF/STA、队列及 TX confirmation。抓包、吞吐量和持续收发需要目标设备验证。

目标 PHY、国家码、信道、加密能力和性能受芯片、配置、AP 与法规共同约束；不要把固定速率、连接数或功耗写成通用保证。
